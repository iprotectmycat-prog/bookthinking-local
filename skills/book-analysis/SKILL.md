# 书籍分析

帮助读者识别一本书或一章最值得理解的内容，理解作者如何展开问题、形成判断或呈现变化，并能回查原文。默认使用用户语言。以用户已有的阅读目标为准；没有具体目标时，说明读懂这些内容能获得什么认识，不替读者断言必须知道什么。

## 输入与路由

- 分析一章或选段：读取 [章节讲解](references/chapter.md)。只为解释本章而读取有依据的相关章节，不擅自扩成整书分析。
- 全书导读或总结：读取 [全书综合](references/book.md)，需要逐章处理时再读取章节讲解。
- 所有正文分析均读取 [来源与覆盖检查](references/evidence.md)。它定义完成条件，而非增加一份面向读者的长报告。
- 只有书名、目录或少量摘要时，产出限于明确标注的初步导读，或说明分析正文还缺什么；已有公开资料可用于用户要求的公开资料综述，不能冒充全文阅读。

## 执行顺序

1. 确认书籍版本、实际可读范围及用户任务。优先使用已提取且可追溯的正文；缺页、乱码、图表未提取等影响理解时，先定位问题并说明影响范围。
2. 先盘点再概括。记录主要正文单元及来源位置，区分序言、正文、注释、附录、目录等角色。序言可解释写作意图，不能代替正文。不要把进程成功或文本非空当覆盖完整。
3. 批量分析先并行分段阅读各章可读正文，保存笔记和各章三句短概括。根据这些概括、目录及可用前言和结语建立暂定全书背景。单章任务可使用已核对的全书背景和前文线索，材料有限时说明依据。
4. 长章按已有小节或连贯主题拆分，保留来源范围；完整流程、推导和案例尽量保持在同一单元。受上下文限制必须拆开时，保存前置条件与衔接记录，再恢复完整关系。AI 拟定的小标题注明是归纳。
5. 批量正式分析可并行复用第一轮的分段笔记。结合本章原文、全书背景和前章短概括，先还原作者在交代的处境、问题或对象，以及内容怎样推进，再选择对理解本章最重要的认识和必要支撑。按具体理解难点拟定可修正的大纲，不预设观点数量。写完讲解后压缩出 3～4 句本章总结，最多 5 句。回查原文分别核对内容理解、重点选择和讲解效果，发现缺漏时修正对应判断。
6. 全书任务根据各章正式分析和原文证据进行跨章综合，回查并修正初读形成的全书背景。输出范围取决于已覆盖内容。
7. 面向读者完成“建立方向 → 连贯讲明白 → 提炼理解 → 留下追问”。先概括本章聚焦与主要认识，主体沿原文的内容关系展开，收束时回到本章问题，交代作者的最终回答或未解之处及其对理解的影响，按需留下有依据的开放追问。它们是表达功能，不是必须重复输出的四个栏目。按需提供来源，不为固定条数填充观点、方法或启发。

## 输出原则

- 重要作者表述有定位，AI 解释与归纳有明确归因。来源支持作者确实如此表达，不自动证明其现实结论正确。
- 深入讲解增加的是必要中间步骤、具体例子与边界；不要仅增加篇幅。作者未给出的例子或类比标为 AI 补充，并指出关键失配处。
- 本章总结帮助读者迅速知道具体讲什么，核心认知提炼重要关系、变化或方法，正文负责把认知讲懂。正文段首直接给出事实、动作或关系，删掉只预告章节内容的导语。
- 对理解有重要作用的原文案例单独标为“作者案例”。先用原文细节讲清谁遇到什么、怎样行动或办理、结果如何，再说明案例的解释作用。正文保留与案例衔接的机制。内部保留来源与定位，默认不在每项认知后展示“原文位置”，引用呈现按另行确定的规则执行。
- 首屏内容不被内部覆盖表、核对日志或技术标识淹没；有实质缺口时，在开头简要交代。证据仍需让读者容易查到。
- 开放追问从本章的具体条件、解释或经验联系生长，区分作者留下的问题与 AI 延伸；它不预设未经验证的事实，不是泛泛的行动建议或必答练习。找不到有价值的追问时允许省略。
- “应用建议”“是否值得读”“复述与练习”仅在阅读目的需要时加入。默认不做章节价值评分，不承诺压缩后保留固定比例的知识，不要求答题才能继续阅读。
- 用户要求文件时保留可编辑文本和来源；未指定格式可用 Markdown。不要自动生成网页、部署服务或改写书库。

## 完成与复用

交付前按来源与覆盖检查逐项核对；分别交代分析范围、重要缺口和未核实的补充。仅检查格式或由模型自检，不能声称已验证准确率或学习效果。

复用旧分析前检查原文版本、解析边界、分析规则和依赖章节是否改变。发生变化时只复用仍适用的内容，重核受影响关系与全书总论；完成记录在相应分析和检查成功后更新。

本 skill 提供 Agent 的分析协议，不自带解析器、自动语义核验器或后台调度。用于 BookThinking 时，产品接入需显式适配现有数据结构；加载本文件不意味着产品提示词已更新。
