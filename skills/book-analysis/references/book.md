# 全书综合

## 综合输入

先建立章节清单及实际覆盖情况，再分析正文。每章记录至少能找回：核心内容、主要部分、关键概念/过程、重要支持与限制、来源范围、缺口。记录可简洁，不要求固定 JSON 或每章相同字段；只有章节一句话结论不足以支持全书综合。

只读目录和序言得到的是暂定的全书路线。后续正文可以修正它。正文不完整时，用户仍可得到局部综合，但开头明确“基于哪些已读章节”，不能把未读章节写成已分析。

批量分析先并行读完各章可读正文并保留分段笔记。依据每章全部笔记写三句短概括，分别说明本章处理什么、作者讲清什么、后文可能需要的概念或条件。没有明确的后文线索时，第三句保留本章判断的必要边界。关键表述关联本章原文。

把各章短概括按书序汇总，结合目录和可用的前言、结语，形成暂定的全书背景，简述全书问题、主要写法和各部分实际推进的路线。可用经核对的同版公开信息辅助了解书籍定位。作者表达和跨章关系回到书内材料判断。读完各章正式分析后，检查初步背景是否遗漏重要章节、把局部判断扩大为全书主张，或错判章节关系。

## 跨章综合动作

1. 重建全书要处理的问题、对象或解释框架；不要默认所有书只有一个中心命题。
2. 说明各部分为何排列在一起，以及每章新增的理解。书中的章节结构与 AI 重新归纳的结构分别说明。
3. 合并真正重复的表达；同名概念在不同语境中含义不同则保留差异。反复出现的同一案例不能计作多个独立证据。
4. 只保留有内容依据的连接：定义、依赖、解释、举例、限制、修正、矛盾等。关系需要两端来源；没有可确认连接时可以保留并列，不能强行把全书画成一棵论证树。
5. 对看似矛盾的地方先比较时间、对象、前提与词义。可以确认的分歧保留；只是可能矛盾则标出需要核对的条件，不能替作者编造统一答案。
6. 重要全书总论回查章节记录和必要原文，检查是否超出了实际材料的支持范围。

## 默认输出

| 部分 | 读者得到什么 |
| --- | --- |
| 全书导读 | 用一段话建立问题、主要表达与阅读入口；有缺口先简要声明 |
| 展开路线 | 各部分如何逐步展开，哪些内容是理解后文的基础 |
| 章节地图 | 每章的核心贡献与必要关系，链接章节讲解；未读章节只列目录信息及状态 |
| 贯穿全书的关键内容 | 概念、机制或主题如何跨章发展；避免重复逐章摘要 |
| 综合理解与未解问题 | 作者明确总结与 AI 跨章归纳可区分；保留有依据的限制和张力 |
| 范围与回查 | 说明已处理/缺失范围，提供重要陈述的来源入口 |

用户只要快速总结时压缩呈现，仍保留必要范围声明和回查入口；不要把工作范围悄悄缩为只读开头。有限预算下先交付明确标记的阶段结果，并说明尚缺的材料。

篇幅与概念数量随内容和任务变化，不承诺固定阅读分钟数或知识覆盖百分比。应用、跳读建议和练习按任务需要另加。
